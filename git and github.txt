What is Git?
    - It's a version control tool which keeps track of changes that's been made to a file/list of files under the directory on which it has been installed.
    - It keeps track of what changed, when changed and who changed.
    - It lets you rollback between various versions of the file.
    - It tracks almost all kinds of files.

Difference between Git and GitHub!
    - Git resides locally in the developer's pc.
    - GitHub resides in the cloud.
    - Summary:
        - Git provides version controlling; GitHub provides remote access and collaboration.

- The folder where you're working on a project is called 'Working Repository'.

- Alternatives of GitHub are GitLab and BitBucket.

- You can have a 'N' number of developers working on a same project, thus having N different versions of the project, under normal circumstances.
    - Solution: GitHub -> A single central remote hub, where all versions being merged into a single version.

- What is a 'Git Repository'?
    - It's a folder where git stores all the versions of a file, it's change history etc on top of few system files.

- To instantiate git in a working directory to keep track of files, use command "git init". 

- "git status" -> A command that lists all changes made to files in the working directory.

- "git add -a || git add --all" -> A command that moves all changes in the working directory to the staging area.

- "git reset" -> This command undo the above step.

- "git add ." -> stage the changes in the current directory inside the working directory.

- "git add *" -> stages only the new file/modified file changes not the deleted file/files.

- "git add <filePath>" -> stage a specific file alone.

- The process of moving the changes from staging area to local repo is called 'COMMIT'.

- To commit, USE "git commit -m <commit_message>".

- "git reset HEAD ~" -> A command to bring back the last commit from local repo to the working directory.

- Assume, you have deleted a file and staged that change.
    - Now, you're reverting the staged change back into working directory using "git reset".
    - Deleted file won't be recovered.
    - To recover the deleted file use, "git reset --hard".

- git rm -f <filePath>
    - forceful deletion of the file in the working repository.

- git rm --cachec <filename>
    - remove the file changes from staging area back into the working directory.

- To view the commits, check COMMIT LOGS.

GIT BRANCHING
    - What's a branch?
        - It's a seperate line of development.
    - To view the branches in your local repo, use 'git branch'.
    - To create a new branch use, 'git branch <branch_name>'.
    - Note: WHEN you create a new branch, the new branch inherits the state of the branch from which it has been created.
    - To switch branches, use "git checkout <branch_name>".
    - To merge a branch with main, switch to the branch and use "git merge -m <merge message>".
    - MERGE CONFLICT:
        - Happens when same file has been modified in 2 different branches.
        - Solution: Manual Resolution.

- To compare various versions/commits, use command "git diff <1st commit> <2nd commit>"
